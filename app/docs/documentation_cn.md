## 基本功能

:::accordion[创建档案]

**步骤 1 — 创建新档案：**
- 点击页眉中的 **"新档案"**。

![说明](create_profil/create_profil_1_de.png)

**步骤 2 — 输入档案名称：**
- 输入档案名称并点击 **"添加"**。
- 点击 **"关闭"** 可不创建档案直接关闭对话框。

![说明](create_profil/create_profil_2_de.png)

**步骤 3 — 了解档案卡片：**

每个档案在列表中以卡片形式显示：

![说明](create_profil/create_profil_3_de.png)

| 编号 | 元素 | 说明 |
|------|------|------|
| ❶ | 拖动手柄 | 通过拖放排序档案 |
| ❷ | Overlay 目标 | 确定哪个档案接收 OCR Overlay 和 Sidepanel |
| ❸ | 辅助目标 | 确定哪个档案作为 CD 计时器的辅助视图 |
| ❹ | 启动模式 | 显示档案以标签还是窗口模式打开 |
| ❺ | 齿轮图标 | 打开档案设置 |
| ❻ | 开始游戏 | 使用此档案启动游戏会话 |

**步骤 4 — 档案设置：**

点击齿轮图标 ❺ 打开设置：

![说明](create_profil/create_profil_4_de.png)

| 编号 | 元素 | 说明 |
|------|------|------|
| ❶ | 档案名称 | 修改档案名称 |
| ❷ | 职业 + 角色名 | 从下拉菜单选择职业并输入角色名。每个角色分配独立的职业。 |
| ❸ | 添加角色 | 向档案添加另一个角色名（点击"添加"按钮） |
| ❹ | 在标签中使用 | 开启：档案可在多标签布局中使用。关闭：档案仅在独立窗口中打开。 |
| ❺ | 保存 | 应用更改 |
| ❻ | 复制档案 | 创建包含所有设置的档案副本 |
| ❼ | 删除 | 永久删除档案 |
| ❽ | 关闭 | 关闭对话框 |

如需在标签和窗口两种模式下使用同一档案，请用 ❻ 复制，每种模式使用一个副本。

**步骤 5 — 带角色的档案列表：**

配置完成的档案在列表中显示角色名和职业图标：

![说明](create_profil/create_profil_5_de.png)

- 每个角色以带职业图标的徽章形式显示在档案名下方。
- 页眉的职业筛选和角色名搜索会搜索所有档案的所有角色。
- 插件（如 Killfeed）通过下拉列表使用已保存的角色名。

可以创建任意数量的档案。每个档案保存独立的 Flyff 会话。
游戏内设置不会像浏览器那样在会话之间共享。

**档案导出/导入：**

![small](create_profil/create_profil_6.png)

| 编号 | 元素 | 说明 |
|------|------|------|
| ❶ | 导出 | 将档案保存为 `.flyffprofile` 文件 |
| ❷ | 导入 | 加载 `.flyffprofile` 文件并创建新档案 |

导出的文件包含：

- 档案元数据（名称、职业、设置）
- Electron 会话 Cookie（登录数据）
- localStorage 数据（游戏设置）

可用于备份和电脑间转移。
:::

:::accordion[创建布局]

**步骤 1 — 启动布局：**

在启用了标签功能的档案上点击 **"开始游戏"**。

![说明](create_layout/create_layout_1_de.png)

**步骤 2 — 选择布局网格：**

选择所需的布局网格。悬停时右侧显示 **ASCII 预览**。

![说明](create_layout/create_layout_2.png)

*对称布局：*
- **1×1** — 单窗口
- **1×2 / 2×1** — 两个窗口并排 / 上下排列
- **1×3 / 3×1** — 三个窗口并排 / 上下排列
- **1×4 / 4×1** — 四个窗口并排 / 上下排列
- **2×2** — 四个窗口网格
- **3+2** — 上方三个，下方两个
- **2×3** — 六个窗口网格
- **4+3** — 上方四个，下方三个
- **2×4** — 八个窗口网格

*非对称布局：*
- **1+2 →** — 主窗口在左，2 个侧窗口在右堆叠
- **1+3 →** — 主窗口在左，3 个侧窗口在右堆叠
- **1+2 ↓** — 主窗口在上，2 个侧窗口在下并排
- **1+3 ↓** — 主窗口在上，3 个侧窗口在下并排

非对称布局在标签栏提供 **滑块**，可调整主窗口和侧窗口之间的分割比例（最小 20% / 最大 80%）。

![small](create_layout/create_layout_slider.png)

**步骤 3 — 分配档案：**

为每个格子分配档案。不需要的格子可留空。

![说明](create_layout/create_layout_3_de.png)

| 编号 | 元素 | 说明 |
|------|------|------|
| ❶ | 布局格子 | 显示所选网格的格子。点击格子可从下方列表分配档案。 |
| ❷ | 档案列表 | 所有启用标签的档案。点击可分配到选中的格子。 |
| ❸ | 下一步 | 确认分配并以分配的档案启动布局。 |

**步骤 4 — 保存布局：**

图片中标记的按钮（在标题栏中）打开保存对话框。

![说明](create_layout/create_layout_4.png)

输入布局名称并点击 **"保存"**。

![说明](create_layout/create_layout_5_de.png)

**步骤 5 — 启动器中的布局卡片：**

保存的布局在档案列表中显示为卡片：

![说明](create_layout/create_layout_6_de.png)

- 卡片显示 **布局名称**、**档案数量** 和 **网格缩略图**。
- 点击 **"开始游戏"** 启动整个布局。
- **齿轮图标** 打开布局设置（名称、档案分配、网格）。

**自定义布局（Custom）：**

除了预定义的网格外，**"自定义"** 选项允许创建自由布局。在编辑器中可以在画布上自由放置和调整 1–8 个单元格的大小。

![描述](custom_layout_editor.png)

| 编号 | 元素 | 描述 |
|-----|---------|-------------|
| ❶ | 添加单元格 | 添加新单元格（最多 8 个）。 |
| ❷ | 网格 | 移动/调整大小时的吸附精度（1%、5% 或 10%）。 |
| ❸ | 滑块 | 设置可调分割线：水平 (↔)、垂直 (↕) 或无 (—)。绿色线条可在编辑器中拖动，用于运行时调整分割。 |
| ❹ | 单元格 | 每个编号的单元格可以拖动移动，并通过角落和边缘的手柄调整大小。 |
| ❺ | 属性 | 所选单元格的 X/Y 位置和宽度/高度（百分比）。也可以直接输入数值。 |
| ❻ | 删除单元格 | 删除当前选中的单元格。 |

重叠的单元格将堆叠显示——顶部单元格接收输入。确认布局后，将像预定义网格一样进行配置文件分配。

**相关设置**（设置 / 布局）：
- **顺序加载网格标签** — 逐个启动标签而非同时启动
- **变更时更新布局** — 自动保存布局更改
- **突出显示活动网格视图** — 视觉上突出当前聚焦的标签
- **布局标签显示模式** — 启动器中布局标签的显示模式
- **布局延迟** — 切换标签时的延迟时间

**相关快捷键**（设置 / 快捷键）：
- **上一个标签** / **下一个标签** — 切换标签
- **下一个窗口** — 在打开的窗口间切换焦点
- **标签栏开/关** — 显示/隐藏会话窗口中的标签栏

**多窗口：**

除布局外还可并行打开多个独立会话窗口。在已有会话时打开档案会询问是添加到当前窗口还是创建新窗口。
:::

:::accordion[数据路径与持久化]

所有用户数据按平台存储在以下目录：

| 平台 | 路径 |
|------|------|

**重要文件和目录：**

| 功能 | 用途 | 相对路径 |
|------|------|----------|
| 档案 | 启动器档案（名称、职业、标记） | `user/profiles/profiles.json` |
| ROI 校准 | OCR/Killfeed 的 ROI 定义 | `user/profiles/rois.json` |
| OCR 计时器 | OCR 采样率 | `user/profiles/ocr-timers.json` |
| 布局 | 标签的网格布局 | `user/ui/tab-layouts.json` |
| 主题 | 用户主题 | `user/ui/themes.json` |
| 活动标签颜色 | 标签颜色设置 | `user/ui/tab-active-color.json` |
| 客户端设置 | 所有启动器设置 | `user/config/settings.json` |
| 功能开关 | 已激活的功能 | `user/config/features.json` |
| Premium 购物清单 | 每个道具的 FCoin 价格 | `user/shopping/item-prices.json` |
| 插件设置 | 各插件的设置 | `user/plugin-data/<pluginId>/settings.json` |
| Killfeed 历史 | 每个档案的每日概览 | `user/plugin-data/killfeed/history/<id>/history.csv` |
| Killfeed 单次击杀 | 按击杀和日期的详细历史 | `user/plugin-data/killfeed/history/<id>/daily/YYYY-MM-DD.csv` |
| API-Fetch 数据 | 插件所需的原始数据/图标 | `user/cache/` |
| 错误日志 | 诊断日志 | `user/logs/` |
| 升级计算器 | 保存的价格/设置 | `user/tools/upgrades/upgrade_cost_calc.json` |

:::

## 控制器

启动器及游戏均可完全通过手柄操控。

::youtube[fSYgnEh36-g]

按键绑定**按配置文件**单独保存，每个角色可拥有独立的布局。


:::accordion[自定义按键绑定]

打开**设置 → 控制器**。

- 在顶部的**配置文件**下选择要编辑绑定的角色。
- 按键按组分类：**面按钮**、**肩键 & 扳机**、**方向键**和**系统 & 摇杆**。
- 点击某个按钮旁的**设置按键**，然后按下所需按键 — 该按键将被保存为目标输入。
- **取消绑定**可移除一项绑定，**默认**将单个按钮重置，**全部重置**则重置整个配置文件。
- 在控制器示意图中，可点击或悬停某个按钮，直接跳转到其绑定设置。
- 点击**保存**应用绑定。

摇杆功能固定不变：**左摇杆 = 移动**，**右摇杆 = 相机**。
:::


:::accordion[特殊操作]

一个按钮除普通按键外，还可以触发**特殊操作**。

| 操作 | 效果 |
|------|------|
| Action-Pad 触发 | 点击游戏 HUD 中的 Action 按钮（攻击/跳跃/互动） |
| 放大 / 缩小 | 拉近 / 拉远镜头 |
| 上一个标签 / 下一个标签 | 在已打开的配置文件标签间切换 |
| 重新加载视图 | 重新加载当前游戏窗口 |
| 切换全屏 | 将启动器窗口切换为全屏 |
| 打开设置 | 打开设置窗口 |
| Ringmaster（转发） | 输入转发给 Ringmaster |
| 点击槽位 1 – 8 | 点击已校准的队伍成员（参见"锁定队伍成员"） |

:::

:::accordion[Action-Pad]

攻击需要使用 D-Pad。

**步骤 1：** 在游戏中启用：菜单 → 选项 → 游戏 → "Directional Pad" **Action-Pad**。

**步骤 2：** 将一个按钮（例如 X）绑定到特殊操作 **Action-Pad**。

**步骤 3：** 在游戏中按 **Ctrl + Shift + F1** 开始校准。

**步骤 4：** 在游戏中的下一次点击将确定 Action-Pad 的锚点。点击 Action 按钮的中心位置。

**结果：** 只要 Action-Pad 可见，即可用所选按钮攻击附近的怪物。

:::

:::accordion[修饰键层]

通过**修饰键层**可实现更多按键绑定。启用后，按住对应肩键时，面按钮（PlayStation 上为 △ ◯ ✕ ☐）可设置多套绑定。

- 在控制器标签中打开**修饰键层**部分。
- 将某个肩键启用为修饰键（开关切换为**开**）。
- 为每个面按钮设置替代操作。"（默认）"将继续使用默认绑定。

:::



:::accordion[Ringmaster 转发]

通过 **Ringmaster 转发**，可在不切换可见窗口的情况下控制后台标签中的 Ringmaster。

**步骤 1：** 在控制器标签的主设置中，于 **Ringmaster 目标**下选择接收转发输入的配置文件。

**步骤 2：** 将特殊操作 **Ringmaster（转发）**绑定到一个按钮。

**步骤 3：** 在游戏中按住转发键 → 所有输入将发送给 Ringmaster。松开 → 输入返回主角色。

**注意：** 目标配置文件必须已打开并已登录。若未满足条件，转发的技能将无效触发。

:::

:::accordion[锁定队伍成员]

通过**名字槽位 1–8** 可将锁定队伍成员的操作绑定到按钮上。

**步骤 1：** 在控制器标签中，例如在 Ringmaster 配置文件上选择**校准槽位 1**。

**步骤 2：** 在游戏中打开队伍窗口（可使用紧凑版本），点击队伍中的第一个名字。

**步骤 3：** 将特殊操作"点击槽位 1"分配给一个按钮。



:::


:::accordion[技能图标选择器]

为了一眼看出哪个技能对应哪个面按钮，可以为每个按钮（✕ ◯ △ ☐）指定一个图标。

- 在控制器标签中，点击对应按钮旁的**选择技能图标**（相机图标）。
- 在选择器中搜索图标，或通过**全部 / 技能 / 物品 / 增益**标签进行筛选。
- 点击图标即可应用；**Shift + 点击**按钮可移除图标。

**提示：** 图标选择器访问图标缓存。显示图标需要 **API-Fetch**（技能，视需求也包括物品）和 **CD-Timer**。

面按钮预览可通过 **Ctrl + Shift** 拖动移位。

:::

## 插件

插件通常需要来自 API 的数据和图标，可通过 API-Fetch 下载。

:::accordion[API-Fetch]

API-Fetch 从 Flyff Universe API 下载数据和图标。其他插件（Killfeed、CD 计时器、Quest Guide、Premium 购物清单）需要这些数据。

- 在设置菜单或 Sidepanel 中打开 **"API-Fetch"**。
![说明](api_fetch/api_fetch_1.png)

- 选择所需的端点并点击 **"Start"**。
![说明](api_fetch/api_fetch_2.png)

进度可实时查看。状态显示哪些端点已处理完成。
由于 API 限制，会有短暂暂停以遵守速率限制。
![说明](api_fetch/api_fetch_3.png)

API-Fetch 也可在 Sidepanel 中使用。
![说明](api_fetch/api_fetch_4.png)

**可用端点：**

| 端点 | 被以下插件使用 |
|------|----------------|
| **Monster** | Killfeed、Giant Tracker |
| **Item** | CD 计时器、Premium 购物清单、Quest Guide |
| **Skill** | CD 计时器 |
| **Quest** | Quest Guide |
| **NPC** | Quest Guide |

:::accordion[CD 计时器]

- 显示图标所需的 API-Fetch："Item" + "Skill"。

- 确认已启用 CD 计时器。

- Sidepanel 中会出现 CD 计时器标签：

- 勾选"Alle aktiv"复选框可激活全部计时器。

  即等待配置的按键输入。

- 计时器图标的显示可配置：X 和 Y 位置、图标大小以及列数。

- 点击"+"可创建新计时器。

- ![说明](cd_timer/cd_timer_3_de.png)

- 点击"Icon"按钮打开图标选择对话框。

  提示：写入需要按的按键，例如"F1"。

  主视图（启动器中的剑图标）或辅助视图（启动器中的法杖图标）。
 此设置决定在哪个窗口中等待按键。
  图标始终显示在主视图窗口中。
 因此你可以为 RM Buff 设置计时器，并在主视图中显示需要刷新的提示。

- ![说明](cd_timer/cd_timer_5_de.png)

:::accordion[Killfeed]
- 通过 OCR 系统实时追踪击杀和经验值（EXP）。
- 显示怪物数据所需的 API-Fetch："Monster"

**功能：**
- 通过 OCR 识别击杀（自动检测 EXP 变化）
- 会话和总计统计（击杀数、EXP、击杀/小时、EXP/小时等）
- Overlay 徽章直接显示在游戏窗口中

**提示：**
- 目前 Killfeed 仅支持 1v1 升级。
- 切换角色时可能会出现混淆。

**设置：**

1. **如未完成：下载 API 数据**
   - 打开插件 [API-Fetch](action:openPlugin:api-fetch)，确保选择了端点 **"Monster"**。
   - 开始下载。需要怪物数据来按经验表验证击杀。
     （见 API-Fetch 文档）
2. **启用插件**
   - 在启动器中打开插件设置，确保 **Killfeed** 已启用。

3. **校准 OCR 区域**（每个档案一次）
   - 通过启动器按下激活的"剑按钮"启动游戏窗口。
   - 在 Sidepanel 中打开 ROI 校准（感兴趣区域）。
   - 在游戏中框选以下显示区域：
     - **EXP%** — 经验值显示
     - **Level** — 等级显示
     - **角色名** — 角色的名称
   - 保存区域。每个档案单独保存，只需设置一次。
   - 左键拖动 ROI。
   - 设置一个 ROI 后可按 TAB 选择下一个。
   - Killfeed 需要设置：LVL、NAME、EXP、ENEMY（敌方等级）、ENEMY HP
   - 按"关闭"或 ESC 完成 ROI 输入。
   - ROI 可在绘制后微调。
   - 识别结果可在 Sidepanel 中实时查看。
   - 最重要的是 LVL 和 EXP；ENEMY 和 ENEMY HP 目前仅起辅助作用，未来会更加重要。
   - 若实时 OCR 的等级显示不正确，可手动设置，
    手动设置的值优先于 OCR 值。
   - 若 OCR 偶尔误读 EXP 值（如切换角色时），可手动重新设置。
     EXP 规则可能会阻止自动纠正。



4. **在 Sidepanel 中选择档案**
   - 打开 Sidepanel，选择 **Killfeed** 标签。
   - 在下拉列表中选择要追踪的档案。
   - 角色名通过下拉列表从档案中选择——无需手动输入。


5. **开始游戏**
   - 击杀怪物后，OCR 系统会检测 EXP 变化。
   - 击杀和统计会自动显示在 Overlay 和 Sidepanel 中。

**Sidepanel：**
- 可切换单个徽章的显示（如 每会话击杀数、EXP/小时、升级所需击杀数）。
- 调整 Overlay 缩放比例（0.6x – 1.6x）。
- 选择徽章跨越的行数。
- Overlay 可通过拖拽移动到游戏窗口中的任意位置。位置会被保存。
- 用重置按钮清空会话统计。
- 每个会话的数据都会本地保存在你的电脑上。



- 每次识别到的击杀都会显示在 Sidepanel 中，并持久保存。
- 数据按档案分别写入 AppData 下的 CSV 文件：
  - `user/plugin-data/killfeed/history/<profile-id>/daily/YYYY-MM-DD.csv`（单次击杀明细）
  - `user/plugin-data/killfeed/history/<profile-id>/history.csv`（每日概览）
- 在怪物追踪折叠面板中，每个阶级都有一个 `Kills` 按钮。
- `Kills` 打开所选阶级的单次击杀列表视图。
-

- 在列表视图中可以删除单次击杀记录（`删除` -> `确认`）。
- 删除后会直接更新 Sidepanel 显示，以及 Killfeed 历史文件（`daily/YYYY-MM-DD.csv` 和 `history.csv`）。



**击杀判定规则：**
满足以下全部条件才计为一次击杀：
- 等级未变化（无升级/降级）。
- EXP 增加超过 0.001%（Epsilon 阈值）。
- EXP 跳变不超过 40%（Suspect 阈值）。更大跳变视为可疑并丢弃。
- 最近 1500 ms 内检测到敌方血条（OCR）。或者：无血条时，与上次击杀间隔至少 2250 ms 也可接受。
- 若存在 API-Fetch 的怪物数据：EXP 增益需介于怪物经验表预期值的 10% 与 10 倍之间。超出范围的值视为 OCR 误差并丢弃。

**被拒绝的 EXP 变化：**
- 升级或降级：不计击杀。
- EXP 下降：忽略（OCR 噪声）。
- EXP 跳变超过 40%：标记可疑，不计入。
- 无血条且距上次击杀少于 2250 ms：不计击杀。

**提示：**
- 必须启用 OCR 系统才能识别击杀。
- 击杀/小时等统计按滚动的 5 分钟窗口计算。

**击杀时间（TTK）：**

TTK 自动测量与 Boss 怪物的战斗时间——从第一次打击到击杀。

*工作原理：*
- **开始：** 检测到敌方 HP 条 `当前 < 最大`（战斗开始）。
- **停止：** 通过 EXP 检测确认击杀。累积的战斗时间被保存。
- **暂停：** HP 条消失（如取消选择目标进行加 Buff 或治疗）。开始 10 秒的宽限期。
- **继续：** 如果在 10 秒宽限期内重新选择同一 Boss 怪物，计时器继续。暂停时间不计入 TTK。
- **中止：** 如果宽限期结束仍未重新选择 Boss，TTK 测量被丢弃。

*目标识别：*
- 战斗开始时保存怪物名称和最大 HP。
- 重新选择时比较名称和最大 HP——只有匹配时计时器才会继续。
- 如果选择了不同的 Boss 怪物，当前测量被中止并开始新的测量。
- 如果选择了普通怪物，Boss 计时器暂停；普通击杀继续计数。

*显示和统计：*
- 紧凑卡片：`TTK: [最后击杀] (平均 [平均值])`
- 展开卡片：平均 TTK、最后 TTK、最快
- TTK 值按击杀保存在 CSV 历史中（`TTK_ms` 列），并按怪物汇总。

*限制：*
- TTK 测量仅对 Giants、Violets 和 Bosses 有效。普通怪物不被测量。
- 精度取决于 OCR 采样率（通常：每 500-1000 毫秒）。

---

**数据来源：**
- 击杀数据来自 Killfeed CSV 历史（`daily/YYYY-MM-DD.csv`）。
- 掉落日志按档案分别存储。
- 怪物详情（图标、HP、ATK、掉落池）来自通过 API-Fetch 下载的怪物数据。
